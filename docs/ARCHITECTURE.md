# mvpMarket — Архитектура прототипа

> Живой документ. Обновляется при каждом согласованном изменении в наполнении
> (страницы, состояния, функционал). История изменений — в разделе
> [Changelog](#changelog) внизу файла.

## 1. Суть проекта

mvpMarket — маркетплейс B2B-услуг/пакетов. **Важное уточнение (2026-09-09):**
единственный поставщик всех товаров/пакетов в каталоге — сама платформа
(mvpMarket), не независимые продавцы; выглядит и ощущается как маркетплейс,
но по сути это витрина одного поставщика (аналог Beeline Business). Прототип
**чисто визуальный**: реального бэкенда, базы данных и авторизации нет (это
будет отдельная большая разработка), но вся навигационная логика, переходы и
состояние интерфейса должны работать как на реальном сайте.

Роли пользователей: **покупатель** и **продавец** (переключение роли — мок,
без реального разграничения прав на сервере). Кабинет продавца как фича
прототипа сохранён (см. роуты `/seller/*`) — это отдельная демонстрационная
возможность "стать продавцом", не противоречащая тому, что основной каталог
наполняет сама платформа.

## 2. Стек

- **React + Vite** — сборка и dev-сервер
- **React Router** — клиентский роутинг между страницами
- **React Context + localStorage** — состояние приложения (без бэкенда)
- Дизайн-система — на входе как HTML/CSS/JS экспорт из Claude Design,
  переносится в переиспользуемые React-компоненты и токены

Бэкенда, БД и серверной авторизации в прототипе нет — все данные это
статические/мок-данные, дополняемые тем, что пользователь создаёт в рамках
сессии (хранится в localStorage).

## 3. Роуты / страницы

| Роут | Назначение |
|---|---|
| `/` | Главная / каталог: список товаров, категории, фильтры, сортировка, поиск |
| `/product/:id` | Страница товара: галерея, описание, отзывы, похожие товары, добавление в корзину/избранное |
| `/cart` | Страница корзины |
| `/checkout` | Оформление заказа (доставка → оплата → подтверждение, мок) |
| `/login`, `/register` | Лёгкая авторизация — визуально, фейковая валидация, создаёт мок-сессию |
| `/profile` | Личный кабинет покупателя: заказы, избранное, настройки |
| `/seller` | Дашборд продавца: простая статистика |
| `/seller/products` | Мои товары (список) |
| `/seller/products/new` | Добавление товара |
| `/seller/products/:id/edit` | Редактирование товара |
| `/seller/orders` | Заказы на мои товары |

### 3.1. Структура страницы `/` (каталог) — референс Beeline Business

Главная/каталог перестроена под конкретный визуальный референс (скриншот
реального B2B-портала Beeline Business), сверху вниз:

1. **Сайдбар** — категории решений (для сотрудников, интернет для бизнеса,
   продажи, управление, IT/облако, безопасность, автоматизация, AI) +
   быстрые ссылки (готовые пакеты, популярное, новинки, избранное, подписки,
   заказы) + блок поддержки
2. **Hero-поиск** — заголовок, строка поиска/ИИ-запроса, голосовой чат
   (декоративно), быстрые промпты-подсказки
3. **Табы сегментов** (все решения / для бизнеса / офис / торговля) +
   сортировка + кнопка "Фильтры" (мобильный drawer с тем же набором фильтров)
4. **Сетка карточек решений** — `SolutionCard`: иконка, теги, чек-лист
   возможностей, цена "от X ₸ в месяц", CTA (`Подключить` либо
   `Начать`+`Информация`) — реально добавляют в корзину
5. **Видео-блок** — декоративный (без реального видео)
6. **"Что выбирают предприниматели"** — интерактивная тарифная карточка
   (переключатель лимит/безлимит, выбор скорости, слайдер ГБ, "Подключить" →
   в корзину) + 3 простые карточки тарифов
7. **"Готовые решения и пакеты"** — горизонтальная лента карточек-пакетов с
   чек-листом технологий, "Добавить в корзину" → реальная корзина
8. **AI-баннер** — промо-градиент, CTA + подсказки-сценарии (клик — подставляет
   текст в hero-поиск и скроллит наверх)

Все "Подключить"/"Добавить в корзину" ведут в тот же `CartContext`, что и
раньше — checkout/профиль/корзина не менялись.

Компоненты — в `src/components/catalog/`; данные (категории, быстрые ссылки,
сегменты, карточки решений, тарифы, пакеты) — единый `src/data/siteContent.js`
через `ContentContext`, см. 3.2.

Из общего лэйаута под этот же референс обновлён футер (мультиколоночный, со
ссылками по категориям и контактным блоком) — см. `src/components/layout/Footer.jsx`.
Шапка (`Header`) не менялась — задача была ограничена главной/каталогом.

### 3.2. Контент главной без кода — `/admin`

Весь контент раздела 3.1 (заголовки, карточки решений, тарифы, пакеты,
AI-баннер, футер, видео-блок) вынесен в единый объект —
`src/data/siteContent.js` (дефолты) + `src/context/ContentContext.jsx`
(состояние с персистентностью в localStorage, CRUD-хелперы, экспорт/импорт
JSON). Компоненты каталога читают контент через `useContent()`, а не из
статических файлов — так же теперь работает и `ProductsContext`
(`content.solutions` — источник каталога товаров для `/product/:id` и
корзины, наравне с товарами, добавленными через кабинет продавца).

`/admin` (ссылка в футере сайта) — редактор без кода: формы по каждому
разделу (текст, цены, чек-листы, картинки — по URL или загрузкой файла как
data:URL), экспорт/импорт JSON, сброс к дефолтам. Правки в `/admin` живут в
браузере того, кто их сделал (как и остальное состояние прототипа); чтобы
они появились у всех посетителей — нужно экспортировать JSON и передать
его для фиксации в `siteContent.js` (см. `docs/content-editing.md`).
`docs/content-template.json` — актуальный снимок дефолтного контента в том
же формате, можно редактировать текстом и прислать взамен похода в `/admin`.

## 4. Состояние приложения

Хранится в React Context, персистится в `localStorage` (переживает
перезагрузку страницы):

- Корзина
- Избранное
- Мок-сессия пользователя (в т.ч. текущая роль: buyer / seller)
- Товары, добавленные продавцом (сразу видны в каталоге — для наглядности демо)
- Контент главной страницы, отредактированный через `/admin` (см. 3.2) —
  до того, как правки экспортированы и зафиксированы в коде, они видны
  только в браузере того, кто их сделал

Данные, не требующие персистентности между сессиями (например, состояние
открытых модалок), живут в обычном React state.

## 5. Оверлеи / выдвижные панели

- **Корзина справа** (drawer) — быстрый доступ из шапки, плюс отдельная
  страница `/cart` для полного вида
- **Фильтры каталога** (drawer) — сворачиваются в выдвижную панель, актуально
  при переходе на мобильную адаптацию
- **Quick view товара** — модалка/панель с карточкой товара без перехода на
  страницу

## 6. Вёрстка / адаптив

Сейчас — фокус на десктоп. Компоненты и layout закладываются так, чтобы
добавить мобильные брейкпоинты позже без переписывания (без хардкода
десктоп-only размеров в логике компонентов, разделение layout- и
контент-компонентов).

## 7. Дизайн-система

Источник (черновик v0.1, получен 2026-09-09) — экспорт из Claude Design
(`.dc.html` + служебный `support.js`, последний не переносится в проект — это
рантайм самого canvas-редактора, не часть дизайн-системы). Токены (цвета,
типографика, spacing, радиусы, тени) зафиксированы как CSS-переменные в
`src/styles/tokens.css`; когда придёт финальная версия дизайн-системы,
обновляются только значения в этом файле — компоненты их не хардкодят.

Ключевые токены черновика: акцент `--color-brand-yellow` (#FFCC00), тёмные
кнопки-действия на `--color-ink` (#1A1A1A), шрифты Onest (текст) и
JetBrains Mono (лейблы/цены), тёплый градиент `--gradient-promo` — не более
одного на экран.

## 8. Структура проекта

```
src/
  styles/          — tokens.css (переменные дизайн-системы), global.css
  components/
    ui/            — базовый кит: Button, Badge, Chip, Tabs, SegmentedControl,
                      Input, Switch, Slider, Card, Price, PlaceholderImage
    overlay/       — Drawer, Modal (общие примитивы для сайдбаров/модалок)
    layout/        — Header, Footer, Layout, CartDrawer, QuickView
    product/       — ProductCard (используется на странице товара/в избранном)
    catalog/       — компоненты главной страницы (CatalogSidebar, HeroSearch,
                      SolutionCard, VideoBlock, BusinessChoiceSection,
                      BundleCarousel, AIBanner, MobileFiltersDrawer)
    admin/         — редактор контента /admin: StringListEditor, ImageField,
                      Admin*Section.jsx (по одной секции на раздел контента)
  context/         — Auth, Content, Products, Cart, Favorites, Orders, UI
                      (открытие/закрытие корзины, фильтров, quick view)
  hooks/           — useLocalStorage
  data/            — siteContent.js (единственный источник контента главной —
                      дефолты для ContentContext, см. 3.2)
  pages/           — по одной странице на роут из раздела 3, включая
                      pages/seller/* (SellerLayout + вложенные страницы) и
                      AdminPage.jsx (роут `/admin`)
```

Изображений товаров по умолчанию нет — используется `PlaceholderImage`
(паттерн "иллюстрация" из дизайн-системы); через `/admin` на карточки,
тарифы и видео-блок можно добавить реальную картинку (ссылкой или файлом).

## 9. Запуск и деплой

Проект — статический SPA-фронтенд без бэкенда, поэтому для запуска не нужен
отдельный сервис с сервером/БД. Два сценария:

### Локально (для разработки и локальной демонстрации)

```bash
npm install
npm run dev       # dev-сервер Vite, обычно http://localhost:5173
```

Для проверки прод-сборки локально:

```bash
npm run build      # соберёт статику в dist/
npm run preview     # поднимет локальный сервер поверх собранной статики
```

Требования: Node.js (LTS, 18+).

### Раскатка как "рабочий сайт" (доступный по ссылке)

Так как это статическая SPA-сборка на мок-данных, полноценный сервер/бэкенд
не нужен — достаточно **статического хостинга**. Рекомендуемые варианты
(zero-config деплой прямо из GitHub-репозитория):

- **Vercel** — деплой по пушу в ветку, preview-ссылка на каждый PR, домен
  вида `*.vercel.app`. Удобно для итеративного показа изменений.
- **Netlify** — аналогично Vercel, тоже с preview-деплоями по PR.
- **Cloudflare Pages** / **GitHub Pages** — более простые бесплатные
  варианты, если preview-деплои на PR не нужны.

Важный момент конфигурации в любом из вариантов: т.к. роутинг клиентский
(React Router), хостинг нужно настроить на **SPA fallback** — все пути
должны отдавать `index.html` (иначе прямой переход по ссылке на
`/product/123` даст 404). Для Vercel это уже сделано — `vercel.json` в
корне репозитория со сквозным rewrite на `index.html`.

Т.к. авторизации, персональных данных и оплаты по-настоящему нет, вопросов
безопасности/секретов на этом этапе нет — достаточно публичного статического
хостинга.

**Деплой на Vercel (выбранный вариант):** привязка идёт напрямую
GitHub↔Vercel через сайт vercel.com (Add New → Project → выбрать репозиторий
и ветку) — доступы/токены никому передавать не нужно. Бесплатного тарифа
Hobby достаточно: он рассчитан на личные/некоммерческие проекты, для
прототипа этого хватает с запасом (свой `*.vercel.app`-домен, автодеплой на
каждый пуш, без привязки карты).
